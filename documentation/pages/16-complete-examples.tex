\chapter{Complete Examples}
\label{chap:complete-examples}

The examples in this chapter assemble the individual keyword pages into complete modelling workflows. Each section describes one physical problem and shows the native FEMaster and supported Abaqus representation side by side. The objective is not to minimize line count: the examples deliberately retain explicit sets, material definitions, Sections, boundary conditions, and analysis controls so the relation between both dialects remains visible.

Where the two input languages expose different abstractions, the examples use the mechanisms actually implemented by the readers. Native FEMaster therefore defines reusable support/load collectors and selects them in \cmd{LOADCASE}; Abaqus input places supported \cmd{BOUNDARY} and load cards inside one \cmd{STEP}. Native truss properties use \cmd{TRUSS SECTION}; the current Abaqus translation uses the supported pure-truss \cmd{SOLID SECTION} mapping.

\section{Linear static truss}

The first example is a two-node axial bar in a consistent N--mm unit system. Node 1 is fixed. At node 2 the transverse translations are constrained while the axial translation remains free. A 1000 N axial load acts in the global \(x\)-direction. With \(E=210000\) MPa, length \(L=1000\) mm, and area \(A=100\) mm\(^2\), the analytical axial displacement is
\[
u_x=\frac{FL}{EA}
=\frac{1000\cdot1000}{210000\cdot100}
\approx 0.047619\ \mathrm{mm}.
\]
This makes the model useful as both a syntax example and a basic solver verification case.

2

\section{Reusable Part and translated Instance}

This example demonstrates the optional semantic model hierarchy. A truss Part is defined in local coordinates and then instantiated after a translation of 500 mm in \(x\). Assembly-level node sets qualify the local node labels with \key{INSTANCE} so supports and loads act on the placed component. The Part itself remains unchanged; the translated coordinates exist only in compiled Assembly data.

The native deck uses the MITC4 formulation directly; the Abaqus deck uses \val{S4}, which the current reader maps to the corresponding FEMaster FRT shell implementation. \section{Eigenfrequency with concentrated tip mass}

The native example attaches a point mass to the free end of a two-element truss and extracts the lowest five eigenpairs. The current Abaqus reader does not translate an equivalent point-mass card, so the Abaqus column demonstrates the supported distributed-mass eigenfrequency model without the concentrated mass. This deliberate difference illustrates an important documentation rule: the right-hand column shows what FEMaster actually accepts rather than pretending unsupported Abaqus syntax is available.

\section{Using the examples as templates}

When adapting an example, preserve the modelling hierarchy before changing numerical detail. First verify that nodes and elements describe the intended reference geometry, then define reusable regions, then attach materials and Sections, then define loads/constraints, and only then tune analysis controls. For imported Abaqus input, remain within the keyword subset documented in this manual: an Abaqus keyword that exists in the commercial Abaqus product is not automatically implemented by the FEMaster reader.

The side-by-side layout is also a translation guide. If a native feature has no Abaqus counterpart in the right column, it should not be added to an Abaqus deck under an assumed spelling. Conversely, Abaqus-specific Step grammar should not be copied into a native FEMaster loadcase. Both routes intentionally converge on the same solver-facing Model and loadcase classes while retaining distinct front-end syntax where appropriate.
