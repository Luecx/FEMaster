\section{Introduction}
\label{sec:introduction}

FEMaster (\emph{Finite Elements in Mechanical Analysis and Simulation for Technical Engineering Research}) is an open-source finite-element solver for structural mechanics, implemented in modern C++. It is designed for engineering applications, scientific research, and education, providing a common framework for the numerical analysis of structures ranging from simple mechanical components to large and complex finite-element models. Its capabilities include different structural element formulations, static and dynamic analyses, eigenvalue problems, and nonlinear structural behavior.

The project originated during the author's university studies, following an internship at MTU where working with CalculiX provided the motivation to develop an independent finite-element solver. Rather than simply reproducing existing functionality, the objective was to implement established numerical methods within a modern, maintainable, and accessible codebase. FEMaster is intended to serve both as a practical engineering tool and as a platform for studying, developing, and verifying finite-element methods. Particular emphasis is placed on numerical transparency, computational performance, and a broad selection of element formulations, allowing users to investigate both the physical response of a structure and the numerical methods used to obtain it.


\section{Design philosophy and implementation}

The development of FEMaster is guided by three closely related objectives: numerical transparency, maintainability, and computational efficiency. Numerical transparency means that the methods used by the solver should be accessible and understandable, rather than hidden behind an opaque implementation. The source code is organized around clearly defined mechanical and numerical concepts, with an emphasis on readable implementations, meaningful interfaces, and documentation. Mathematical formulations and numerical procedures are described throughout this manual where appropriate, providing a connection between the theoretical foundations of finite-element analysis and their implementation in the solver. This is particularly relevant for educational applications, method development, and the verification of numerical results.

Maintainability is supported by a modular C++ architecture that separates model definitions, element formulations, material behavior, analysis procedures, and numerical solution methods. This separation allows individual components to be developed and examined without requiring detailed knowledge of the entire application. It also facilitates the implementation of additional element formulations, constitutive models, and analysis capabilities. The intention is to maintain a codebase that remains approachable as the solver grows in complexity, enabling contributions and modifications without sacrificing the clarity of existing implementations.

Computational efficiency is addressed through parallel execution, efficient numerical algorithms, and established high-performance libraries. FEMaster uses Eigen for linear algebra operations and Spectra for eigenvalue computations, while Intel oneMKL provides high-performance multithreaded CPU solution capabilities. GPU acceleration is supported through NVIDIA CUDA and cuDSS, allowing computationally demanding solution tasks to be executed on compatible graphics hardware. The available numerical backends depend on the platform and build configuration. These technologies are intended to provide efficient solutions for both small models, where computational overhead can be significant relative to the actual problem size, and large systems, where memory requirements and the performance of sparse numerical operations become increasingly important.


\section{Input format and compatibility}
\label{sec:input-compatibility}

FEMaster uses a unified keyword-based input format derived from the conventions established by Abaqus and also used by CalculiX. A finite-element model is described through a text file containing definitions for geometry, element connectivity, materials, structural properties, loads, boundary conditions, and analysis procedures. The format is particularly suitable for automated model generation, parameter studies, and reproducible numerical investigations, while remaining sufficiently readable for small models to be created and modified manually.

The input language supports a subset of the Abaqus keyword syntax together with FEMaster-specific extensions. Both forms are interpreted within the same input language and can generally be combined in a single input deck. This allows existing Abaqus-style models to be used where their definitions are supported, while additional FEMaster keywords provide access to functionality beyond the conventional syntax. Full compatibility with arbitrary Abaqus input files is not implied, since the supported keywords, parameters, element formulations, and numerical procedures depend on the capabilities implemented in FEMaster. The Keyword Reference documents these capabilities and presents alternative Abaqus-compatible and FEMaster-specific syntax wherever applicable.

Several extensions introduce concepts inspired by preprocessing environments such as Altair HyperWorks. In particular, loads and supports can be organized into named collectors that are defined independently of individual analyses. These collectors can subsequently be referenced by analysis steps, allowing different combinations of loads and boundary conditions to be applied without repeatedly defining the same conditions. Additional keywords provide explicit control over analysis procedures, constraint handling, solver selection, and the use of CPU or GPU acceleration. Together, these extensions are intended to make input decks easier to organize, reuse, and inspect, particularly when a model contains several loading configurations or analysis procedures.


\section{Supported element families}

FEMaster provides a range of structural finite elements for modelling one-, two-, and three-dimensional mechanical behavior. The supported families include truss, beam, shell, continuum solid, and point elements, each offering different capabilities and levels of geometric detail. The choice of element formulation determines which deformation modes can be represented, which physical properties are required, and how accurately a particular structural response can be captured.

An important characteristic of FEMaster is its support for six mechanical degrees of freedom per node, consisting of three translations and three rotations. Individual elements activate only the degrees of freedom required by their formulation. In particular, beam and shell elements use independent rotational degrees of freedom and are implemented as dedicated structural elements. Unlike the approach used for many conventional beam and shell formulations in CalculiX, these elements are not internally expanded into three-dimensional continuum elements. Instead, their stiffness, internal forces, and other mechanical quantities are evaluated directly from their respective structural formulations.

\textbf{Continuum solid elements} represent the full three-dimensional deformation and stress state of a body. FEMaster supports tetrahedral, hexahedral, wedge, and pyramid elements with different interpolation orders and integration schemes, including reduced integration and enhanced formulations. They are particularly suitable for complex geometries, local stress concentrations, and regions where three-dimensional effects are important.

\textbf{Beam and truss elements} provide computationally efficient representations of slender structures. Truss elements carry axial forces, while beam elements additionally represent bending, torsion, and transverse shear, depending on the formulation. Their cross-sectional behavior is defined through geometric and material properties rather than an explicitly meshed cross-section. FEMaster supports both classical beam formulations and geometrically exact formulations capable of representing finite rotations, making them suitable for frames, stiffeners, spars, and other structural members.

\textbf{Shell elements} describe thin-walled structures through a two-dimensional reference surface and associated thickness properties. They capture membrane deformation, bending, and transverse shear without requiring a volume mesh through the thickness. FEMaster includes shell formulations based on the Mixed Interpolation of Tensorial Components (MITC) approach with finite-rotation kinematics, making them suitable for plates, panels, curved shells, and lightweight structures.

\textbf{Point elements} introduce concentrated properties such as masses, rotary inertias, and spring stiffnesses at individual nodes. They allow attached equipment, payloads, and simplified elastic supports to be represented without explicitly modelling their geometry.

The different element families can be combined within a single finite-element model, allowing an appropriate balance between computational efficiency and mechanical detail. The available element types, their formulations, numerical characteristics, and limitations are documented in Section~\ref{sec:elements}.


\section{Supported analysis families}

FEMaster supports several analysis procedures covering static structural behavior, stability, free vibration, and time- or frequency-dependent response. An analysis procedure determines the governing equations to be solved, the required system matrices, and the numerical strategy used to obtain the solution. The same finite-element model can be evaluated using different procedures, allowing structural stiffness, deformation, stability, and dynamic characteristics to be investigated without redefining the underlying geometry and material properties. The currently supported analysis families are summarized below.

The solution is obtained through iterative equilibrium corrections, with support for load-controlled increments and arc-length path following. Free-vibration analysis based on the generalized eigenvalue problem of the structural stiffness and mass matrices. The analysis procedures differ not only in their numerical solution methods but also in the physical assumptions underlying their results. Linear static analysis and linearized eigenvalue procedures are generally efficient and suitable for a wide range of engineering investigations, provided their assumptions are appropriate for the problem. Nonlinear static analysis extends the equilibrium formulation to situations in which the structural response changes with deformation, loading, or contact conditions, but typically requires incremental loading and iterative convergence. Dynamic procedures additionally account for mass and inertia, either by integrating the response over time or by evaluating the steady-state response at selected excitation frequencies. These distinctions should be considered when selecting a procedure, since the most computationally demanding analysis is not necessarily the most appropriate one for a particular engineering question.

Both FEMaster-specific analysis definitions and supported Abaqus procedure keywords are available within the input language. The corresponding Abaqus procedures include \cmd{STATIC}, \cmd{FREQUENCY}, \cmd{BUCKLE}, \cmd{DYNAMIC}, and \cmd{STEADY STATE DYNAMICS}. Their accepted parameters, available numerical controls, and relationship to the FEMaster analysis types are documented in Section~\ref{sec:analysis-procedures}.


\section{Degree-of-freedom convention}

FEMaster uses a generalized six-component nodal convention consisting of three translations and three rotations:
\[
    \dofvec.
\]
The first three components represent translational displacements along the global coordinate axes, while the last three represent rotational degrees of freedom about those axes. This convention is used for generalized nodal loads, supports, coupling definitions, initial velocities, and selected result Fields. It does not imply that every node necessarily contributes six degrees of freedom to the global equation system. The active degrees of freedom depend on the connected element formulations and associated model definitions. For example, continuum solid elements generally require only translations, whereas beam and shell elements additionally use rotations. This distinction permits different structural element families to be represented within a common generalized framework without introducing unnecessary degrees of freedom throughout the model.

The six-component nodal convention must not be confused with the six-component engineering stress and strain convention, which represents the independent components of symmetric second-order tensors rather than generalized displacements. Stress and strain component ordering is documented in Section~\ref{sec:output-results}.


\section{Units}

FEMaster does not prescribe a particular system of units or perform automatic unit conversions. All geometric dimensions, material properties, loads, masses, and numerical parameters must therefore be expressed using a consistent system of units. A common choice for structural analysis is millimetres, newtons, tonnes, and seconds, resulting in stresses and elastic moduli expressed in megapascals. Other systems, such as metres, newtons, kilograms, and seconds, are equally valid when applied consistently. Particular attention is required for density, rotary inertia, dynamic loading, damping coefficients, thermal expansion, and stiffness-related parameters, since inconsistent units may produce numerical results that appear plausible despite having no meaningful physical interpretation. Responsibility for unit consistency remains with the user, and the solver interprets all supplied quantities according to the governing finite-element equations.
