\chapter{Constraints}
\label{chap:constraints}

Constraints introduce kinematic relations between degrees of freedom that go beyond ordinary supports. A support prescribes selected degrees of freedom directly. A constraint instead relates the motion of different nodes or regions, for example by connecting a reference node to a surface, tying two independently meshed regions together, defining an idealized joint, or removing rigid-body motion from an otherwise free component.

The distinction between these constraint types is physical, not merely syntactic. A kinematic coupling imposes a rigid relation between selected motions. A structural/distributing coupling transfers generalized motion and loading between a reference point and a distributed region. A Tie creates a permanent compatibility relation between associated geometry. A Connector idealizes a joint between two points. RBM removes the rigid-body nullspace of a selected structural region. Contact, described at the end of this chapter, is unilateral and allows separation.

Constraints are used by the active analysis together with the selected support collectors. The numerical method used to enforce the resulting equations is controlled separately by \cmd{CONSTRAINTMETHOD}; see Chapter~\ref{chap:numerical-controls}.

\keywordpage{COUPLING}

\cmd{COUPLING} relates one master or reference node to a slave region. The master is given as a node set and must contain exactly one node. The slave can be a nonempty node set selected with \key{SLAVE} or a nonempty surface set selected with \key{SFSET}; exactly one of these two slave definitions must be used.

\key{TYPE=KINEMATIC} creates a kinematic coupling. The selected slave degrees of freedom follow the rigid kinematics induced by the reference node. This is useful when a region should move as if connected to a rigid reference point, for example at an idealized rigid flange, a load-introduction point, or a boundary where deformation of the coupled patch is intentionally suppressed in the selected directions.

\key{TYPE=STRUCTURAL} creates the distributing form. It is intended for transferring generalized loads and motions between a reference point and a distributed region without making the complete slave region rigid in the same sense as a kinematic coupling. This is generally the more appropriate choice when a force or moment is to be introduced through a reference point while the connected surface should still be able to deform according to the surrounding structure.

The data line contains six selector values in the order
\[
(U_x,U_y,U_z,R_x,R_y,R_z).
\]
A component is active when the supplied value is greater than zero. Missing values are inactive. These six values are therefore \emph{selectors}; they are not prescribed displacement or rotation magnitudes.

For a surface slave, the distribution is based on the selected surface geometry. For a node-set slave, the supplied node region itself defines the coupled region. In either case the reference-node set must contain exactly one node so that the generalized motion and loading have an unambiguous reference point.

\begin{keywordparameters}
\key{MASTER} & required & Node set containing exactly one master/reference node. \\
\key{TYPE} & required & \val{KINEMATIC} or \val{STRUCTURAL}. \\
\key{SLAVE} & conditional & Nonempty slave node set; mutually exclusive with \key{SFSET}. \\
\key{SFSET} & conditional & Nonempty slave surface set; mutually exclusive with \key{SLAVE}. \\
\end{keywordparameters}

\begin{keyworddata}
Six DOF selectors & Positive value enables the corresponding \(U_x,U_y,U_z,R_x,R_y,R_z\) relation; omitted values are inactive. \\
\end{keyworddata}

\exampleheading

\begin{dialectexamples}
\begin{femasterdeck}
*COUPLING, MASTER=REF,
 SFSET=LOADED_FACE, TYPE=STRUCTURAL
1., 1., 1., 0., 0., 0.
\end{femasterdeck}
\begin{noabaqus}
The supported Abaqus reader currently does not import the Abaqus coupling keyword family. Define the coupling with native FEMaster syntax when this relation is required.
\end{noabaqus}
\end{dialectexamples}

\notesheading

A distributing coupling is often preferable to applying identical concentrated nodal forces to all nodes of a surface. The latter changes the total load when the mesh is refined, while a reference-point load combined with a distributing coupling represents a definite resultant force or moment.

Use a kinematic coupling only when the corresponding rigid relation is physically intended. Coupling a large deformable surface kinematically can add substantial artificial stiffness even though the solver satisfies the equations exactly.

\keywordpage{TIE}

\cmd{TIE} creates a permanent kinematic connection between slave geometry and master geometry located within a prescribed search distance. The slave may be a node set or a surface set. The master may be a surface set or a line set. FEMaster selects the appropriate supported tie relation from these region types.

\key{DISTANCE} defines the geometric search tolerance used to associate slave locations with the master geometry. It should be large enough to capture the intended interface but not so large that unrelated geometry becomes a possible match. \key{ADJUST=YES} permits the supported initial adjustment of slave geometry to the tie relation; the default is \val{NO}.

A Tie represents a bonded or otherwise permanently connected interface. Once the relation has been established, opening or sliding that violates the selected compatibility equations is not permitted. It is therefore appropriate for idealized bonded interfaces, mesh transitions, or connections that are assumed not to separate. It is not appropriate for interfaces that may open, close, or lose contact; use \cmd{CONTACT} for that case.

The accuracy of a Tie depends on the geometric relation between the two discretizations. Avoid unnecessarily large search distances and inspect the interface when meshes are highly nonmatching, strongly curved, or close to other candidate master surfaces.

\begin{keywordparameters}
\key{MASTER} & required & Nonempty master surface or line set. \\
\key{SLAVE} & required & Nonempty slave node or surface set. \\
\key{DISTANCE} & required & Search/projection distance used to associate slave and master geometry. \\
\key{ADJUST} & optional & \val{NO} (default) or \val{YES}. \\
\end{keywordparameters}

\exampleheading

\begin{dialectexamples}
\begin{femasterdeck}
*TIE, MASTER=MASTER_FACE,
 SLAVE=SLAVE_NODES,
 DISTANCE=0.5, ADJUST=YES
\end{femasterdeck}
\begin{noabaqus}
Abaqus \cmd{TIE} is currently not imported by the FEMaster Abaqus reader, even though the native solver provides Tie constraints.
\end{noabaqus}
\end{dialectexamples}

\notesheading

Tie and contact solve different modelling problems. A Tie is an equality-type connection and remains active. Contact is unilateral: it transmits normal interaction only while the contact condition is active and permits subsequent separation.

If a nominally bonded interface is modelled with a Tie, the connection stiffness is governed by the surrounding structure rather than by an artificial penalty spring. If compliance of an adhesive layer or joint is physically important, model that compliance explicitly rather than using Tie merely because the surfaces are close.

\keywordpage{CONNECTOR}

\cmd{CONNECTOR} defines an idealized kinematic joint between two nodes. \key{NSET1} and \key{NSET2} each identify a node set containing exactly one node. \key{COORDINATESYSTEM} specifies the local connector axes, and \key{TYPE} selects which relative translations and rotations are constrained or released.

The supported connector types are \val{BEAM}, \val{HINGE}, \val{CYLINDRICAL}, \val{TRANSLATOR}, \val{JOIN}, and \val{JOINRX}. They represent different idealized joint kinematics. For example, a hinge is intended to release a rotational degree of freedom about its local hinge axis while constraining the remaining relative motion required by that joint idealization. A translator and a cylindrical connector likewise rely on their local axis system to define the permitted relative motion.

The coordinate system is therefore part of the physical definition, not a cosmetic orientation. Always verify the local connector axes, especially when the connected nodes lie in arbitrary three-dimensional geometry. A correct joint type with an incorrect axis can produce a perfectly converged but physically wrong model.

Connectors are best used for idealized joints whose internal geometry does not need to be resolved. If bearing deformation, bolt bending, local contact, joint clearance, or detailed connection stress is important, replace the idealized connector with an appropriately detailed beam, shell, solid, spring, or contact model.

\begin{keywordparameters}
\key{TYPE} & required & \val{BEAM}, \val{HINGE}, \val{CYLINDRICAL}, \val{TRANSLATOR}, \val{JOIN}, or \val{JOINRX}. \\
\key{NSET1} & required & First one-node set. \\
\key{NSET2} & required & Second one-node set. \\
\key{COORDINATESYSTEM} & required & Named coordinate system defining the connector axes. \\
\end{keywordparameters}

\exampleheading

\begin{dialectexamples}
\begin{femasterdeck}
*ORIENTATION, NAME=HINGE_AXES,
 TYPE=RECTANGULAR
1., 0., 0., 0., 1., 0.

*CONNECTOR, TYPE=HINGE,
 NSET1=PIN_A, NSET2=PIN_B,
 COORDINATESYSTEM=HINGE_AXES
\end{femasterdeck}
\begin{noabaqus}
Connector translation is currently not part of the supported Abaqus input subset.
\end{noabaqus}
\end{dialectexamples}

\notesheading

If a distributed region is to be connected through an idealized joint, first reduce the region to a meaningful reference node using a coupling and then connect the reference nodes. This keeps the joint definition independent of the surface mesh density.

\keywordpage{RBM}

\cmd{RBM} suppresses the rigid-body modes of a selected structural element region without requiring the user to choose arbitrary fixed nodes. The target is specified by \key{ELSET} or its alias \key{SET}; if omitted, \val{EALL} is used.

A free three-dimensional body has six rigid-body modes: three translations and three rotations. These modes have no elastic strain energy and therefore produce a structural nullspace when no physical support removes them. RBM constructs constraint equations that remove the rigid-body motion of the selected region while avoiding the strong local bias that can arise from fixing one arbitrary corner node in several directions.

RBM is useful when the numerical problem requires the rigid-body nullspace to be removed but no particular physical support point is intended. It should not be used to conceal a genuinely incomplete boundary-condition model. If the real structure is attached through bearings, bolts, symmetry, contact, or other supports, those physical constraints should normally be represented directly.

RBM is also different from inertia relief. RBM changes the admissible kinematics by suppressing rigid motion. Inertia relief retains the free-body interpretation and balances the applied load with an equivalent rigid-body inertial field.

\begin{keywordparameters}
\key{ELSET} / \key{SET} & optional & Nonempty target structural element set; default \val{EALL}. \\
\end{keywordparameters}

\exampleheading

\begin{dialectexamples}
\begin{femasterdeck}
*RBM, ELSET=FREE_COMPONENT
\end{femasterdeck}
\begin{noabaqus}
No direct RBM-suppression keyword is currently imported by the supported Abaqus reader.
\end{noabaqus}
\end{dialectexamples}

\notesheading

Use RBM when removing rigid-body motion is itself the intended mathematical constraint. Do not use it as a general cure for singular systems: a singularity may instead indicate disconnected parts, released mechanisms, missing sections, unsupported rotational degrees of freedom, or an incorrect constraint definition.
